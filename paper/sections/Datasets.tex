\section{Datasets}\label{sec:datasets}
The four instances provided with the challenge (NYT, HAN, FOS and PES) are text files with a \texttt{V E} header followed by four sections: \texttt{[NODES]} with \texttt{id x y source\_flag}, \texttt{[EDGES]} with \texttt{u v capacity}, \texttt{[OFFICE]} with the id of the office node used in T6, and \texttt{[NEW]} with \texttt{x y capacity} for each node to insert in T7. Node attributes are therefore the id, the coordinates and the source flag. The only edge attribute is the third column, which the challenge slides call the pipe capacity and label as the diameter in their figures \citep{narvaez_slides}; it is used as the capacity in T5 and never as a length. Lengths are computed from the coordinates in T2. Table~\ref{tab:datasets} summarises the instances after validation.

The loader checks every record and logs problems instead of failing. It drops malformed or non-finite values, pipes to unknown nodes, self-loops and non-positive capacities, keeps a repeated pipe only once, and flags coincident coordinates, gaps in the ids, header counts that do not match the data, a missing office, and \texttt{[NEW]} points outside the network's bounding box enlarged by 50\% on each side. No value is missing or invalid in any file, but three things are unexpected. PES lists pipe 28-30 twice, once as \texttt{28 30} and once as \texttt{30 28} with the same capacity; it is kept once, so PES has 98 pipes rather than the declared 99, and the capacity of that pipe is not doubled in T5. The PES ids run from 1 to 89 with 18 gaps, which an id-to-index map handles. NYT's second \texttt{[NEW]} point, $(6478,3050)$, lies 4.6 network widths east of NYT's eastern edge and is identical to HAN's second entry, so it is treated as a copy error and not inserted.

All four instances are connected and have exactly two sources. NYT and HAN are almost trees (2 and 3 independent loops), so most nodes have a single route to a source, while FOS and PES are meshed (22 and 28 loops). Six of the eight sources are leaves (both sources of NYT and HAN, source 37 of FOS and source 7 of PES), so a single pipe joins each of them to the rest of the network. All networks are very sparse: the density $2E/(V(V-1))$ ranges from 0.039 (PES) to 0.111 (NYT). Figure~\ref{fig:networks} draws the four networks on their original coordinates.

Computationally, each instance is held in a \texttt{Network} object: a dictionary from node id to coordinates, the list of sources, the list of pipes as $(u,v,c)$ triples, the office and the accepted new nodes. The algorithms run on structures derived from it, an adjacency list and an adjacency matrix (Section~\ref{sec:implementation}); T1 compares the two.
